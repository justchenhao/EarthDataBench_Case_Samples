# Atlantic δ¹³C-DIC Observations, Point Reconstruction, and 3-D Climatology

## Objective

Use the supplied Atlantic cruise observations, GLODAPv2.2023 point predictors, GLODAPv2.2016b mapped predictors, and monthly atmospheric xCO2 to construct three linked products: a secondary-quality-controlled public observation table, a fixed-support Atlantic point reconstruction, and a `1° × 1° × 33-depth` Atlantic climatology. The sole formal scientific quantity is the stable carbon isotope composition of dissolved inorganic carbon, δ¹³C-DIC, expressed in per mille relative to VPDB. Point and gridded products must also report comprehensive uncertainty and quality or support information. Preserve declared missing support; do not fill it with an author product, interpolation, constants, or climatology.

## Input

- `input/qc_observation_source.csv.gz` contains 96,079 non-private rows from the 51-cruise compilation after removal of two whole-cruise test sets. It retains source row identifier `observation_id`, `expocode`, year, month, nine ocean predictors, raw δ¹³C-DIC, and source flags. Numeric source missing values are encoded as `-9999`.
- `input/cruise_adjustments.csv` contains one row for each of the 49 public cruises. `additive_adjustment_per_mille` is the paper Table 1 additional adjustment to apply to the archived raw value; the archived raw field already incorporates any applicable Becker et al. adjustment. A blank adjustment denotes the explicitly rejected poor cruise. `eligible_for_model` identifies cruises retained for model development.
- `input/point_prediction_support.csv.gz` contains exactly 152,127 GLODAPv2.2023 Atlantic rows with all ten predictors finite. `sample_id` is the fixed source-row identifier. The five source flags accompany the predictors; no author reconstruction or private test label is present.
- `input/grid_prediction_support.nc` is a NETCDF4 file on the native `depth=33, lat=180, lon=360` GLODAPv2.2016b grid. It contains float64 `depth`, `lat`, and `lon`; uint8 `valid_mask`; float32 `temperature`, `salinity`, `aou`, `nitrate`, `silicate`, and `dic` plus corresponding `_error` fields; and scalar float64 `xco2`. The mask has 289,219 valid Atlantic cells, defined only from public predictor validity and longitude. AOU was derived as oxygen solubility minus mapped oxygen, and the timeless xCO2 value is the unweighted mean of all monthly values from 1972-01 through 2013-12.
- `input/xco2_monthly_1972_2023.csv.gz` contains the complete 624-month Mauna Loa xCO2 sequence used for observation and point dates and for auditing the timeless grid reduction.
- `input/README.md` states the public QC and training rules. `input/input_manifest.json` records relative paths, byte sizes, SHA-256 hashes, support counts, and the disclosed reconstructed grid choices. Provenance records are not additional production inputs.
- This is a bounded reconstructed Case. The paper does not publish an executable formula for a small row-wise 2023 cruise micro-adjustment or a per-record author uncertainty array; do not claim exact reproduction of those unavailable steps.

## Product construction

1. Verify the input manifest and process all rows in deterministic identifier order. Treat numeric `-9999` as missing before scientific calculations. Do not infer withheld rows from identifier gaps.
2. Construct the QC product on every public `observation_id`. Join the adjustment table by exact `expocode`. If raw δ¹³C-DIC is missing, write `-9999` and quality flag `9`. If the adjustment is blank while raw δ¹³C-DIC is finite, write `-9999` and flag `3`. Otherwise write `raw + additive_adjustment`; assign flag `2` only when `eligible_for_model=1` and source `c13_flag` is `2` or `6`, and assign flag `3` otherwise. The small unavailable 2023 row-wise micro-adjustment must not be reverse-engineered from any reference.
3. Form model training rows only where the QC output has flag `2`; all nine ocean predictors are finite; and `c13_flag`, `salinity_flag`, `aou_flag`, `nitrate_flag`, `silicate_flag`, and `dic_flag` are each `2` or `6`. Join monthly xCO2 by the observation's calendar year and month. Use the ten predictors in this order: longitude, latitude, depth, temperature, salinity, AOU, nitrate, silicate, DIC, and xCO2.
4. Standardize predictors using training rows only. Fit one deterministic nonlinear regression relationship aligned with the paper's standardized Matérn-5/2 Gaussian-process design. Assign point quality flag `2` when all five supplied source flags are `2` or `6`, otherwise assign `3`. Values must be finite on all point rows and remain within the declared physical range.
6. Estimate mapping uncertainty without private data, using predictive spread or deterministic grouped/cross-validated residual diagnostics from public training data. Define comprehensive uncertainty by root-sum-square propagation of `0.07‰` observation uncertainty, mapping uncertainty, and an input-variable contribution; the paper reports representative mapping and input contributions of approximately `0.08‰` and `0.009‰`. Keep every submitted point and valid-grid uncertainty finite within `0.07–1.0‰`, and document whether it varies spatially or is a conservative bounded estimate.
7. Apply the same trained relationship to every cell where `valid_mask=1` in `grid_prediction_support.nc`, using its coordinates, six mapped ocean predictors, and scalar xCO2. Write `-9999` for both target variables wherever `valid_mask=0`. Do not use the author grid to derive a mask, fill predictor gaps, interpolate target values, or alter coordinates.
8. Supply complete deterministic code that regenerates all three products and the representative figure from the listed public inputs. Record input verification, QC counts, training counts, model and scaling choices, uncertainty propagation, quality counts, grid support, software versions, the executed command, and known reconstructed limitations.

The methodology must be nonempty valid UTF-8 and the production program must be syntactically valid Python. The `0.4` and `0.6` gates require both expert-product agreement and independent-validation non-inferiority; the `0.8` and `1.0` gates then add strict independent improvement. Private reference values, support identities, comparison thresholds, and scoring implementation are not disclosed.
